# china_bot — Telegram-бот для практики китайского языка

Голосовой ИИ-собеседник для практики китайского. Юзер шлёт голосовое, бот отвечает
голосом на китайском, правит ошибки и оценивает произношение по тонам. Бесплатный
дневной лимит, дальше подписка.

Бот: [@ChineseToneBot](https://t.me/ChineseToneBot)

## СНАЧАЛА ПРОЧИТАЙ ЭТО

Работа ведётся по методологии `/okplan`. **Перед любой задачей выполни протокол
старта сессии**, иначе будешь работать по устаревшей картине:

1. Прочитать `docs/STATUS.md` — текущий этап, активная работа, блокеры
2. `git tag -l "stage-*"` — сверить с колонкой «Закрывающий тег» в STATUS.
   Тег есть, а в таблице нет → STATUS устарел, сначала чинить его
3. `git log --oneline -10` — что менялось последним
4. Открыть `docs/07_ROADMAP.md` на текущем этапе, там открытые чекбоксы

Приоритет источников правды: **git-тег > чекбоксы в ROADMAP > проза STATUS**.
Если тега `stage-N-done` нет, этап не закрыт, что бы ни говорил STATUS.

## Стек

Python 3.12, aiogram 3.x, FastAPI, SQLAlchemy 2.0 async + asyncpg, Alembic,
Redis, arq (очередь), structlog, pydantic-settings, ffmpeg, ruff, pytest.
Всё в Docker.

Внешние сервисы и кто за что отвечает:

| Что | Сервис | Роль |
|---|---|---|
| Диалог, грамматика, перевод | OpenRouter | работает с ТЕКСТОМ, звук не слышит |
| Распознавание речи | OpenAI Whisper | голос юзера в текст |
| Озвучка | Fish Audio | голос бота на китайском |
| Оценка произношения | SpeechSuper | единственный, кто слышит ЗВУК |
| Платежи | LavaTop | карты и СБП |

Все четыре подключаются через слой-абстракцию `app/core/providers/`, провайдер
выбирается переменной окружения. За проект уже дважды отваливались сервисы по
антифроду (Azure, потом Alibaba), поэтому смена провайдера должна быть настройкой,
а не переписыванием.

## Как ведётся работа

**Один этап за раз.** Не забегать вперёд, не делать этап 5, пока не закрыт 4.

Этап закрывается **только после живой проверки человеком**. Claude не ставит
галочки и теги сам по факту написания кода. Порядок закрытия:

1. Все чекбоксы этапа в ROADMAP реально выполнены
2. Человек проверил вживую, результат записан в «Историю закрытий» STATUS
3. `git tag stage-N-done -m "..."`
4. `chore(status): close stage N`

Коммиты статуса отдельно от кода: `chore(status): start stage N`.

## Правила кода

- Логика **не живёт** в хендлерах aiogram. Хендлер разбирает апдейт, зовёт сервис
  из `app/core/services/`, рисует ответ. Это граница, по которой потом
  подключится вебапп
- Миграции только через Alembic, автонакат при старте контейнера, даунгрейд
  обязателен в каждой ревизии
- Правка `.py` перезапускает процесс сама (watchfiles), пересборка образа нужна
  только при смене зависимостей
- Логировать **каждую щель**: входящие, ответы, вызовы внешних сервисов с
  длительностью и стоимостью, ошибки с телом ответа, движения денег, задачи очереди.
  Логи на русском, с датой, username, user_id, first_name. `request_id` в каждой
  записи, чтобы реплика собиралась в цепочку
- Секреты в логи не попадают, маскируются процессором structlog
- Тексты интерфейса в `app/bot/texts/`, а не в коде хендлеров
- Тяжёлое (голосовой круг, рассылки) уходит в arq, не выполняется в обработчике апдейта
- Отвечать на русском
