## 1. Что за продукт

Голосовой ИИ-собеседник для практики китайского. Аналог, показанный клиентом,
это @ChattyChineseBot.

Пользователь наговаривает голосовое, бот отвечает голосом на китайском, правит
ошибки, показывает пиньинь с переводом и оценивает произношение по тонам.
Есть бесплатный дневной лимит, дальше подписка.

Ключевая ценность и главный риск это **голос бота как эталон произношения**.
Если эталон врёт по тонам, ученик заучивает ошибку. Отсюда все решения по TTS.

Навигация и путь пользователя описаны отдельно в [`02_NAVIGATION.md`](02_NAVIGATION.md).
Архитектурные заделы под будущие продажи в [`03_GROWTH.md`](03_GROWTH.md).

## 3. Инфраструктура на машине разработки

Docker уже поднят, **на сервере пока ничего нет**. Разработка идёт локально.

Что уже крутится и переиспользуется:

| Контейнер | Образ | Порт |
|---|---|---|
| `postgres16` | postgres:16 (16.14) | 5432 |
| `redis` | redis:alpine | 6379 |
| `supabase_*` | чужой проект | не трогать |

В `postgres16` уже живут чужие базы (`landing_bot`, `sbavito`, `mydb`).

**Своя база и свой пользователь обязательны.** Не селимся в чужие базы и не пишем
в `public` общей базы.

```sql
create user china_bot with password '...';
create database china_bot owner china_bot;
```

Alembic держит свою таблицу версий внутри этой базы. Redis используется с отдельным
префиксом ключей `china:` и своим номером базы, чтобы не пересечься с соседями.

Наш `docker-compose.yml` поднимает только приложение и воркер, а к postgres и redis
подключается по сети хоста. Это осознанно: на сервере компоуз будет поднимать всё,
локально базы уже есть и дублировать их незачем.

## 4. Раскладка кода

Граница между Telegram и логикой проведена жёстко. Хендлеры разбирают апдейт,
зовут сервис и рисуют ответ. Логики в хендлерах нет.

```
app/
  bot/
    handlers/        только Telegram: команды, кнопки, FSM
    keyboards/       клавиатуры и inline-разметка
    middlewares/     логирование, лимиты, троттлинг, юзер в контекст
    texts/           тексты интерфейса, ничего в коде хендлеров
  core/
    services/        вся логика: dialog, pronunciation, limits, billing, progress, streak
    providers/       внешние сервисы за интерфейсами
      llm/           openrouter
      stt/           openai_whisper
      tts/           fish, (minimax, elevenlabs на будущее)
      pronunciation/ speechsuper
    events.py        журнал событий, функция track()
  db/
    models/          модели SQLAlchemy
    repositories/    доступ к данным
    session.py
  api/               FastAPI: вебхук LavaTop, health, задел под вебапп
  worker/            arq: обработка голосового круга, рассылки
  config.py          pydantic-settings
  logging.py         настройка structlog
migrations/          alembic
docs/                ТЗ, роадмап, статус
tests/
docker/
```

Причина такой границы: вебапп следующим этапом это HTTP-слой поверх тех же
`core/services`, а не переписывание бота. Подробнее в [`03_GROWTH.md`](03_GROWTH.md).

## 5. Голосовой круг

```
голосовое юзера (ogg/opus)
   │
   ├─ (1) STT      OpenAI Whisper, голос → текст (китайский и русский)
   ├─ (2) LLM      OpenRouter: ответ по-китайски, разбор ошибок, пиньинь, перевод
   ├─ (3) TTS      Fish Audio, текст ответа → аудио
   └─ (4) ffmpeg   в ogg/opus, иначе Telegram покажет файлом, а не голосовым
```

Круг целиком уходит в очередь arq, а не выполняется в обработчике апдейта.
Пользователю сразу отправляется «печатает» или запись голоса, результат приходит
отдельным сообщением. Так круг переживает всплески нагрузки и сбои внешних сервисов.

Норма задержки 8-12 секунд, это подтверждено на живых замерах.

Разделение ролей, чтобы не путать в коде:

- **OpenRouter** отвечает за смысл, диалог, грамматику, перевод. Работает с текстом,
  звук не слышит вообще
- **SpeechSuper** отвечает за произношение и тоны, единственный, кто слышит звук
- **STT** голос в текст, **TTS** текст в голос

## 6. Внешние сервисы

| Что | Сервис | Цена | Ключ |
|---|---|---|---|
| Диалог | OpenRouter | ~$0.0005 за реплику | есть |
| Распознавание | OpenAI Whisper | $0.006/мин | есть |
| Озвучка | Fish Audio | $15 за 1 млн знаков | есть |
| Произношение | SpeechSuper | $0.006 за проверку, минимум $20/мес | есть |
| Платежи | LavaTop | комиссия провайдера | есть |

Все четыре подключаются **через слой-абстракцию** в `core/providers/`. Провайдер
выбирается переменной окружения. Это не украшательство: за проект уже дважды
отвалились сервисы по антифроду (Azure, потом Alibaba), третий раз вопрос времени.

### Fish Audio, детали

- База `https://api.fish.audio`, заголовок `Authorization: Bearer <key>`
- Синтез `POST /v1/tts`, заголовок `model: s1`, тело `{text, format, reference_id, prosody}`
- Ответ бинарный, не JSON
- Голос задаётся `reference_id`, темп через `prosody.speed` (проверено, работает)
- Баланс API отдельный от платформенного, подписки Plus и Pro покупать не нужно

Голоса выбирать осторожно: библиотека Fish в основном народные клоны реальных
людей. Для коммерческого бота нужны дикторские и нейтральные.

### SpeechSuper, детали

- `POST https://api.speechsuper.com/<coreType>`, coreType `sent.eval.cn`
- Подписи SHA1: connect `sha1(appKey + ts + secretKey)`,
  start `sha1(appKey + ts + userId + secretKey)`
- Аудио строго WAV 16 кГц, моно, 16 бит, конвертируем через ffmpeg
- Требует эталонный текст, отсюда механика «повтори за мной», см. раздел 7.3

## 7. Функционал

### 7.1 Вход

`/start` → приветствие → выбор уровня HSK (1-2, 3-4, 5-6 или «не знаю») → сразу
разговор. От запуска до первой сказанной фразы не больше двух нажатий.

Для «не знаю» короткий тест из трёх вопросов на слух, по ответам ставим уровень.

Уровень HSK это не отдельные версии бота, а параметр в базе, который подставляется
в промпт и в скорость озвучки.

### 7.2 Разговор

Принимаем голосовое и текст, на русском и на китайском. Отвечаем голосовым плюс
тем же текстом иероглифами.

Ошибки правим мягко, отдельным текстовым блоком, чтобы не ломать голосовой поток.

Под каждым ответом три inline-кнопки и строка счётчика «осталось 7 из 10 на сегодня».

### 7.3 Три кнопки под ответом

- **Текст** — пиньинь со знаками тонов и перевод на русский. Данные уже посчитаны
  на шаге LLM, дополнительных вызовов нет
- **Помощь** — 2-3 варианта, что ответить, с переводом каждого
- **Оценка** — разбор произношения

Механика «Оценки» неочевидна и зафиксирована здесь намеренно. Оценить произношение
«вообще» невозможно, сервису нужен эталонный текст для сравнения. Поэтому кнопка
работает как «повтори за мной»:

1. Эталоном берётся последняя фраза бота, либо исправленный вариант фразы юзера,
   если тот ошибался
2. Бот пишет «повтори за мной» и озвучивает эталон
3. Юзер записывает голосовое
4. SpeechSuper сравнивает запись с эталоном
5. Показываем общий балл и балл на каждый иероглиф, отмечаем сбитые тоны
6. Кнопки «Послушать эталон» и «Попробовать ещё раз»

Полный JSON ответа сервиса сохраняем в базу целиком, не только итоговую цифру.

### 7.4 Настройки

Уровень HSK, голос (у каждого кнопка «Прослушать»), скорость речи (медленно,
обычно, быстро), тема разговора (свободная, знакомство, еда, дорога, работа,
магазин, учёба).

Тема это подмена промпта, а не отдельный сценарий.

### 7.5 Прогресс

Стрик «12 дней подряд», календарь месяца с закрашенными днями практики, суммарные
счётчики, средний балл произношения в динамике.

### 7.6 Лимиты

Считаем **сообщения**, не токены и не минуты. Пользователь видит и контролирует
только их.

- Первые 3 дня после старта: 30 голосовых в день
- Дальше: 10 голосовых и 3 разбора произношения в день
- Сброс в полночь по Москве
- Отдельный счётчик на разбор, потому что это самая дорогая операция в проекте

Все числа лежат в базе и меняются из админки без деплоя. Это обещано клиенту.

Счётчик показывается под ответом заранее, а не только в момент исчерпания, чтобы
человек принимал решение о подписке спокойно.

### 7.7 Подписка и оплата

Провайдер **LavaTop**. Оплата картами и через СБП.

Подписка это сущность, а не булев флаг: таблицы `plans` и `subscriptions`.
Это открывает годовой тариф, промокоды, подарки и рефералку без переделки биллинга.

Вебхук LavaTop принимает FastAPI, проверяет подпись, идемпотентно активирует
подписку по `external_id`. Повторный вебхук не должен продлевать дважды.

### 7.8 Админка

Вход по списку telegram id из конфига. Разделы: лимиты и длина пробного периода,
цена подписки, статистика (юзеры, платящие, конверсия, расход по сервисам),
рассылка всем или сегменту.

## 8. Данные

Схемы приведены сокращённо, точные типы в моделях.

```sql
users(id uuid pk, created_at, hsk_level, voice_id, speech_speed, topic, tz)
identities(user_id, provider, ext_id, pk(provider, ext_id))
```

Пользователь и способ входа разделены сразу: `telegram_id` не должен быть
первичным ключом во всех таблицах, иначе вход в вебапп потребует миграции всей базы.

```sql
plans(code pk, title, price, duration, limits jsonb)
subscriptions(id, user_id, plan_code, status, started_at, expires_at, source, external_id)
payments(id, user_id, provider, external_id unique, amount, status, raw jsonb, created_at)

dialogs(id, user_id, role, text_zh, pinyin, translation, audio_file_id, created_at)
pronunciation_checks(id, user_id, ref_text, score, detail jsonb, created_at)

events(id bigserial, user_id, type, payload jsonb, created_at)
prompts(code pk, version, body, updated_at)
settings(key pk, value jsonb)
daily_usage(user_id, date, messages, checks, pk(user_id, date))
```

Про `events`: пишем туда вообще всё, что делает пользователь, с первого дня.
Аналитика продаётся отдельным этапом, и без накопленной истории она покажет пустоту.

Оперативные счётчики лимитов живут в Redis (быстро, TTL до полуночи), в
`daily_usage` дублируются для истории и аналитики.

## 9. Логирование

Требование заказчика работ: **каждая щель под отладку**. structlog, вывод
человекочитаемый локально и JSON на сервере.

Логируем обязательно:

- каждое входящее сообщение и нажатие кнопки: дата, username, user_id, first_name,
  тип, содержимое
- каждый ответ бота с текстом ответа
- каждый вызов внешнего сервиса: имя провайдера, длительность, размер запроса
  и ответа, стоимость в символах или секундах, http-код
- каждую ошибку внешнего сервиса с телом ответа
- переходы состояний FSM
- срабатывание лимита, старт и конец пробного периода
- любое движение денег: создание платежа, вебхук, активация, продление
- запуск и завершение задач в очереди, время выполнения, ретраи
- миграции при старте

Каждая запись несёт `request_id` и `user_id` через contextvars, чтобы одна реплика
собиралась в цепочку от входящего голосового до отправленного ответа.

Тексты сообщений в логах на русском. Секреты в логи не попадают никогда, ключи
маскируются на уровне процессора structlog.

## 10. Миграции и автосборка

**Миграции.** Alembic. Ревизии генерируются из моделей
(`alembic revision --autogenerate`), накатываются автоматически при старте
контейнера через entrypoint (`alembic upgrade head`), до запуска бота. Даунгрейд
обязателен в каждой ревизии.

**Автосборка при изменениях.** В dev-режиме код примонтирован томом, процесс
перезапускается на изменение файлов через `watchfiles`. Пересобирать образ ради
правки в коде не нужно. Пересборка требуется только при смене зависимостей.

Для боевого режима отдельный сервис компоуза без монтирования и без watchfiles.

## 11. Деплой и CI/CD

Сервер из доступов, Ubuntu. Разворачивается по навыку `/okdeploy`.

- GitHub Actions по пушу в `main`: линт, тесты, сборка образа
- Деплой по SSH: `git pull`, `docker compose up -d --build`, прогон миграций
- Секреты в GitHub Secrets, на сервере в `.env`, который в репозиторий не попадает
- Health-эндпоинт FastAPI для проверки живости после деплоя
- Откат: предыдущий образ и `alembic downgrade` при поломке миграции

## 14. Приёмка

Работа ведётся по методологии `/okplan`: **один этап за раз**, каждый заканчивается
тем, что можно потрогать руками. Этап закрывается только после живой проверки
человеком, потом ставится тег `stage-N-done`.

Этапы и критерии приёмки в [`07_ROADMAP.md`](07_ROADMAP.md), текущее состояние
в [`STATUS.md`](STATUS.md).

Общие условия сдачи:

- бот работает на сервере клиента, не на машине разработки
- исходный код передаётся клиенту
- две недели после сдачи ошибки исправляются бесплатно
- правки по согласованному функционалу входят в стоимость, новые функции
  обсуждаются отдельно
