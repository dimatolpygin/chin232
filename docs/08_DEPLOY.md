# Сервер и деплой

Развёрнут досрочно, на этапе 5: без публичного https вебхук платёжки проверить
нечем. Этап 10 останется на обвязку — бэкапы, мониторинг, автозапуск обновлений.

## Что где

| Что | Значение |
|---|---|
| Хост | `104.143.218.104`, Ubuntu 24.04, 2 ГБ RAM, 58 ГБ диска |
| Домен | `chinesetonebot.ru`, A-запись на тот же IP, регистратор reg.ru |
| Каталог проекта | `/opt/china_bot` |
| Публичный вход | Caddy на хосте, `/etc/caddy/Caddyfile`, сертификат сам |
| Доступ по ssh | root, пароль в `dostupi.txt` |

Наружу открыт только вебхук и `/health`, всё остальное отдаёт заглушку: API
не должен светиться в интернет целиком. Порт `8090` слушает `china_api`, наружу
он не публикуется, Caddy ходит на него через `127.0.0.1`.

Контейнеры: `china_bot`, `china_worker`, `china_api`, `china_postgres`,
`china_redis`. В отличие от машины разработки, база и redis тут свои, в томах
`china_pgdata` и `china_redisdata`.

Свопа на машине не было, а 2 ГБ памяти для сборки образа мало: добавлен файл
`/swapfile` на 2 ГБ, прописан в `/etc/fstab`.

## Как выкатить изменения

Репозиторий на GitHub пустой, код уезжает с машины разработки архивом:

```bash
git archive --format=tar HEAD -o /tmp/china.tar
pscp /tmp/china.tar root@104.143.218.104:/root/
ssh root@104.143.218.104
cd /opt/china_bot && tar -xf /root/china.tar && rm /root/china.tar
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Миграции накатываются сами при старте `china_bot`, отдельной команды не нужно.

`.env` на сервере свой и в архив не попадает: пароль базы и секрет вебхука там
сгенерированы отдельно от машины разработки. При распаковке архива он не
затирается, но проверять после каждого деплоя стоит.

## Грабли, на которые уже наступили

**CRLF в `entrypoint.sh`.** Разработка на Windows, скрипт уехал с CRLF, и все
три контейнера падали в цикле с `exec docker/entrypoint.sh failed: Permission
denied` — tini не находит интерпретатор из-за `\r` в шебанге. Лечится
`.gitattributes` с `*.sh text eol=lf`, он в репозитории.

**Dev-монтирования уезжали в прод.** Прод-оверрайд глушил их пустым
`volumes: []` — так это не работает: пустой список ничего не отменяет, compose
оставлял бинды из базового файла. На сервер уезжал код с хоста, а вместе с ним
`entrypoint.sh` без бита запуска, и контейнеры снова падали с Permission denied.
Починено разделением: dev-монтирования переехали в `docker-compose.override.yml`
(compose подхватывает его сам локально и не подхватывает при боевой команде с
двумя явными `-f`), а сам `entrypoint.sh` теперь лежит в репозитории с правами
`100755`.

**Один токен на два процесса.** Telegram не отдаёт апдейты двум поллерам сразу.
Пока бот работает на сервере, локальный контейнер `china_bot` должен быть
погашен, иначе оба валятся с 409. Для параллельной разработки нужен отдельный
тестовый бот у @BotFather.

## Проверка живости

```bash
curl https://chinesetonebot.ru/health
docker ps --format '{{.Names}}\t{{.Status}}'
docker logs china_bot --tail 20
```

Вебхук отвечает `401` на чужой ключ и `200` на верный — быстрый способ убедиться,
что Caddy проксирует, а секрет в `.env` совпадает с кабинетом платёжки.

## Автовыкатка через GitHub Actions

Джоба `deploy` в `.github/workflows/ci.yml` срабатывает на пуш в `main` и только
после зелёных `lint-and-test` и `secrets-check`. Она заходит на сервер по ssh
отдельным ключом, делает `git reset --hard origin/main`, пересобирает образ,
поднимает контейнеры и ждёт зелёного `/health`. Если здоровье не поднялось за
сто секунд, джоба падает — молчаливой выкатки сломанного бота не будет.

`.env` на сервере автовыкатка не трогает: он в `.gitignore`, `git reset --hard`
его не видит. Миграции накатывает `entrypoint.sh` при старте контейнера.

Ключ доступа отдельный, ed25519, создан только для выкатки: приватная часть
лежит в `.secrets/deploy_key` (каталог в `.gitignore`), публичная — в
`/root/.ssh/authorized_keys` на сервере. Личный пароль root в Actions не
передаётся.

Секреты репозитория (Settings → Secrets and variables → Actions):

| Имя | Что кладём |
|---|---|
| `SERVER_HOST` | адрес сервера |
| `SERVER_USER` | `root` |
| `SSH_PRIVATE_KEY` | приватный ключ выкатки целиком, вместе со строками BEGIN и END |
| `SERVER_HOST_KEY` | строка known_hosts с отпечатком сервера |

Секреты заведены 20.08.2026, `/opt/china_bot` превращён в клон репозитория,
пайплайн прогнан вживую до зелёного: пуш в `main` собрал, прогнал тесты,
выкатил и дождался `/health`. Ручная выкатка архивом больше не нужна, она
остаётся только на случай, когда GitHub недоступен.

Ещё одни грабли оттуда же: в шагах workflow имена переменных только латиницей.
bash на раннере падает на кириллическом идентификаторе с `not a valid
identifier`, и джоба помечает успешную выкатку как провал.

## Бэкапы и логи

Дамп базы каждую ночь в 03:30 через `/etc/cron.d/china_backup`, скрипт
`/opt/backup/pg_dump.sh`, файлы `china_bot-ГГГГ-ММ-ДД.sql.gz` в `/opt/backup`.
Хранится неделя, дальше затирается, отчёт дописывается в `/opt/backup/backup.log`.

Восстановление:

```bash
gunzip -c /opt/backup/china_bot-2026-08-20.sql.gz | \
  docker exec -i china_postgres psql -U china_bot -d china_bot
```

Дампы лежат на том же диске, что и база: от потери сервера они не спасают.
Съём копий на сторону — на этапе 10.

Логи Docker ограничены в `/etc/docker/daemon.json`: 20 МБ на файл, 5 файлов на
контейнер. Без этого json-file пишет без предела и однажды забивает диск.
