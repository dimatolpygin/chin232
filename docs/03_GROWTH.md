# Оси роста, что заложить сейчас

Документ для нас, не для клиента. Смысл: сделать так, чтобы будущие продажи
(вебапп, аналитика, курсы, рефералка) были дописыванием, а не пересборкой.

Правило, из которого всё следует: **закладываем данные и границы, а не функции**.
Функция дописывается когда угодно. Данные, которые не начали собирать, задним
числом не восстановить. Граница, которую не провели сразу, потом вскрывается
только через переписывание половины кода.

Всё ниже добавляет к разработке примерно полтора-два дня и укладывается
в согласованные 16-20 дней. Цену пересматривать не нужно.

---

## 1. Журнал событий. Самое важное

Одна таблица, куда пишется вообще всё, что делает юзер.

```sql
create table events (
  id         bigserial primary key,
  user_id    uuid not null,
  type       text not null,      -- message_sent, button_clicked, limit_hit, paid, ...
  payload    jsonb,              -- детали события, свободная форма
  created_at timestamptz default now()
);
create index on events (user_id, created_at);
create index on events (type, created_at);
```

**Что открывает:** любую аналитику задним числом. Воронку от /start до оплаты,
ретеншн по когортам, на каком шаге отваливаются, сколько разборов делают перед
покупкой, какие темы популярнее.

**Почему сейчас:** если начать собирать события в момент заказа аналитики,
у клиента будет ноль исторических данных. Он купит дашборд, который полгода
показывает пустоту. Если события пишутся с первого дня, аналитика продаётся
как «включим то, что уже накоплено», и это гораздо более лёгкая продажа.

**Цена сейчас:** таблица и одна функция `track()`. Полдня.

## 2. Бизнес-логика отдельно от Telegram

Хендлеры Telegram не содержат логики. Они разбирают апдейт, зовут сервис,
рисуют ответ.

```
bot/handlers/      только Telegram: кнопки, тексты, клавиатуры
core/services/     вся логика: dialog, pronunciation, limits, billing, progress
core/providers/    внешние сервисы за интерфейсами
db/                доступ к данным
```

**Что открывает:** вебапп. Мини-приложение это второй интерфейс к тем же
сервисам, ему нужен только HTTP-слой поверх `core/`. При такой раскладке
вебапп это новая папка, а не операция на открытом сердце.

Дальше по той же границе идут мобильное приложение и партнёрский доступ.

**Почему сейчас:** если логика размазана по хендлерам, вебапп означает либо
дублирование логики (два места, где считаются лимиты, гарантированно разъедутся),
либо рефакторинг всего бота за счёт разработчика.

**Цена сейчас:** ноль. Это просто дисциплина раскладки файлов с первого дня.

## 3. Подписка это сущность, а не флаг

Не `users.is_premium boolean`, а нормальная модель.

```sql
create table plans (
  code       text primary key,        -- free, month, year, gift_30
  title      text,
  price      numeric,
  duration   interval,
  limits     jsonb                    -- сколько сообщений и разборов в день
);

create table subscriptions (
  id          uuid primary key,
  user_id     uuid not null,
  plan_code   text references plans(code),
  status      text,                   -- active, expired, cancelled, trial
  started_at  timestamptz,
  expires_at  timestamptz,
  source      text,                   -- lavatop, promo, gift, manual
  external_id text                    -- id платежа у провайдера
);
```

**Что открывает:** годовой тариф, промокоды, подарочные подписки, рефералку
(начисление через ту же таблицу с `source = referral`), ручную выдачу доступа
блогеру, пробные периоды любой длины.

**Почему сейчас:** булев флаг это тупик. Рефералка и подарки поверх него
означают переделку биллинга целиком, а это самая нервная часть кода, потому
что она про деньги.

**Цена сейчас:** две таблицы вместо одного поля. Пара часов.

## 4. Внешние сервисы за интерфейсом

Уже решено по озвучке после истории с Alibaba. Распространяем на все четыре.

```js
// core/providers/tts/index.js
const provider = require(`./${config.tts.provider}`);  // fish | minimax | elevenlabs
module.exports = { synth: (text, opts) => provider.synth(text, opts) };
```

Так же для STT, LLM и оценки произношения.

**Что открывает:** смену провайдера при блокировке или подорожании, разные
провайдеры на разных тарифах (дешёвая озвучка бесплатным, лучшая платным),
переезд на своё железо.

**Почему сейчас:** два антифрода подряд, Azure и Alibaba. Третий вопрос времени.

**Цена сейчас:** почти ноль, если делать сразу.

## 5. Контент живёт в базе, а не в коде

Темы разговора, системные промпты под уровни HSK, стартовые фразы, тексты
интерфейса лежат в таблицах.

```sql
create table prompts (
  code       text primary key,      -- dialog_hsk12, topic_food, correction
  version    int default 1,
  body       text,
  updated_at timestamptz
);
```

**Что открывает:** новые темы без деплоя, курсы и уроки как контент, а не как
разработку, подгонку тона бота по отзывам за пять минут. Версия рядом с промптом
нужна, чтобы понимать, какой версией сгенерирован ответ, когда сравниваем качество.

**Почему сейчас:** «добавьте тему про путешествия» должно стоить клиенту одну
строку в админке, а не оплаченный час. Это ещё и снимает поток мелких бесплатных
правок в нашу сторону.

**Цена сейчас:** таблица и загрузка при старте. Пара часов.

## 6. Результаты оценки сохраняем целиком

SpeechSuper возвращает подробный разбор: балл на каждый иероглиф, тон, пиньинь,
беглость. Сохраняем весь JSON, а не только итоговую цифру.

```sql
create table pronunciation_checks (
  id         uuid primary key,
  user_id    uuid,
  ref_text   text,
  score      int,
  detail     jsonb,              -- полный ответ сервиса
  created_at timestamptz
);
```

**Что открывает:** «твои слабые места: третий тон и звук zh», динамику по
конкретным звукам за месяцы, персональные тренировки на проблемные тоны.
Это очень хорошая будущая продажа, и она невозможна без накопленной истории.

**Почему сейчас:** данные уже приходят, их надо просто не выбрасывать.

**Цена сейчас:** ноль, вопрос одного поля.

## 7. Пользователь и способ входа это разные вещи

```sql
create table users (
  id         uuid primary key,      -- внутренний, вечный
  created_at timestamptz
);

create table identities (
  user_id  uuid references users(id),
  provider text,                    -- telegram, web, apple
  ext_id   text,
  primary key (provider, ext_id)
);
```

**Что открывает:** вход в вебапп, привязку второго канала, будущее приложение.

**Почему сейчас:** если `telegram_id` разложен первичным ключом по всем таблицам,
добавление второго способа входа это миграция всей базы.

**Цена сейчас:** одна дополнительная таблица.

## 8. Настройки и флаги в базе

Общий key-value конфиг плюс переопределения на конкретного юзера.

**Что открывает:** A/B тесты («половине даём 15 сообщений, смотрим на конверсию»),
бета-доступ к новым функциям, индивидуальные условия для блогера или крупного
клиента, аварийное отключение дорогой функции без деплоя.

**Цена сейчас:** таблица и функция чтения с кешем в Redis. Пара часов.

---

## 9. Тяжёлая обработка через очередь

Голосовой круг уходит в очередь Redis, обрабатывается воркером, а не прямо
в обработчике апдейта.

**Что открывает:** горизонтальное масштабирование (несколько воркеров на одну
базу), ретраи при сбое внешнего сервиса, ограничение одновременных запросов
к платным API, любые фоновые задачи потом: рассылки, отчёты, ночные пересчёты.

**Почему сейчас:** синхронная обработка живёт до первой сотни одновременных
юзеров, потом упирается и переделывается вместе со всей обвязкой.

**Цена сейчас:** полдня, Redis всё равно в стеке ради лимитов.

---

## 10. Язык обучения как параметр

Нигде в коде не зашито, что предмет это китайский. Язык лежит в настройках
и подставляется в промпты, выбор голоса и коды сервисов.

**Что открывает:** запуск японского или корейского бота на том же движке.
Для клиента это новый продукт и новая выручка, для нас почти чистая маржа,
потому что переиспользуется всё, кроме контента и оценки произношения.

**Цена сейчас:** дисциплина. Не писать `chinese` там, где должно быть
`config.language`.

## Чего НЕ делать

Соблазн перестраховаться приведёт к тому, что 60к превратятся в 200к работы.
Сознательно не закладываем:

- микросервисы, всё живёт одним процессом плюс воркер
- абстракции над базой на случай смены Postgres, смены не будет
- плагинную архитектуру и систему расширений
- event sourcing и CQRS
- Kubernetes, хватит docker compose на одном сервере
- мультитенантность и white label до появления второго заказчика
- собственную систему A/B со статистикой, достаточно флагов

Всё перечисленное решает проблемы, которых у проекта нет и, скорее всего,
не будет.
