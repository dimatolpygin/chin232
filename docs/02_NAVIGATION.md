# Навигационная карта бота

Что юзер видит и куда может ткнуть. Это основа для ТЗ, все экраны ниже
попадают в разработку. Тариф «Репетитор», 60 000 ₽.

Обозначения: `[кнопка]` это inline-кнопка под сообщением,
`«раздел»` это кнопка нижнего меню, оно видно всегда.

---

## Уровень 0. Вход, один раз в жизни

```
/start
  │
  ├─ приветствие, одно короткое сообщение
  │
  ├─ выбор уровня          [HSK 1-2]  [HSK 3-4]  [HSK 5-6]
  │                        [Не знаю свой уровень]
  │                             │
  │                             └─ 3 вопроса на слух, бот сам определяет
  │
  ├─ бот озвучивает первую фразу, чтобы юзер сразу услышал голос
  │
  └─► ЭКРАН РАЗГОВОРА
```

Ключевое: от /start до первого голосового не больше двух нажатий.
Регистрация, анкеты и туториалы отсутствуют, обучение идёт по ходу.

---

## Уровень 1. Нижнее меню, доступно всегда

```
🗣 Общение   📈 Прогресс   ⚙️ Настройки   💎 Подписка   ❓ Помощь
```

«Общение» это состояние по умолчанию. Юзер может ничего не нажимать вообще
и просто говорить, бот будет отвечать.

Пока в меню четыре кнопки в две строки: «Общение» на всю первую, «Профиль»,
«Прогресс» и «Подписка» втроём на второй. Раздел настроек называется у юзера
«Профиль». «Помощь» появится на своём этапе — кнопка, за которой пусто, хуже
отсутствующей.

---

## Уровень 2. Экран разговора, главный экран

```
юзер шлёт голосовое (или текст, на русском либо на китайском)
  │
  └─ бот отвечает голосовым + тем же текстом иероглифами
       │
       ├─ [Текст]     пиньинь и перевод ответа бота
       ├─ [Помощь]    2-3 варианта, как ответить, с переводом
       └─ [Оценка]    разбор произношения, см. уровень 3
       │
       └─ строка снизу: «осталось 7 из 10 на сегодня»
```

Если юзер ошибся, бот сначала мягко поправляет, потом продолжает разговор.
Исправление приходит текстом, чтобы не ломать голосовой поток.

Когда лимит исчерпан:

```
«На сегодня бесплатные сообщения закончились»
  ├─ [Оформить подписку]  ─► Уровень 2, Подписка
  └─ [Напомнить завтра]      бот пишет сам, когда лимит обновится
```

---

## Уровень 3. Оценка произношения, отдельная ветка

Здесь важное проектное решение. Оценить произношение «вообще» нельзя,
сервису нужен эталонный текст для сравнения. Поэтому кнопка работает
как «повтори за мной».

```
[Оценка]
  │
  ├─ бот берёт эталоном свою последнюю фразу
  │  (или исправленный вариант фразы юзера, если тот ошибался)
  │
  ├─ «Повтори за мной: 今天天气很好»  + озвучка эталона
  │
  ├─ юзер записывает голосовое
  │
  └─ результат:
       общий балл, например 78 из 100
       иероглиф за иероглифом: 今 100 · 天 100 · 天 45 · 气 90 · 很 100 · 好 60
       где сбит тон, отмечено отдельно
       [Послушать эталон]  [Попробовать ещё раз]
```

Лимит на разбор отдельный от лимита сообщений, потому что операция самая
дорогая в проекте.

## Уровень 2. Настройки

```
⚙️ Настройки
  ├─ Уровень            [HSK 1-2] [HSK 3-4] [HSK 5-6]
  ├─ Голос              список голосов, у каждого [Прослушать]
  ├─ Скорость речи      [Медленно] [Обычно] [Быстро]
  └─ Тема разговора     [Свободная] [Знакомство] [Еда] [Дорога]
                        [Работа] [Магазин] [Учёба]
```

Тема это подмена промпта, а не отдельный сценарий. Бот начинает разговор
сам и держится темы, пока юзер не сменит её.

## Уровень 2. Прогресс

```
📈 Прогресс
  ├─ стрик: «12 дней подряд»
  ├─ календарь месяца, дни с практикой закрашены
  ├─ всего сообщений, всего разборов произношения
  └─ средний балл произношения и как он менялся
```

Смысл раздела в удержании. Стрик это главная причина вернуться завтра.

Как сделано (этап 7). Серия не рвётся, пока идёт сегодняшний день: занимался
вчера, зашёл утром — видит серию целой, а не обнулённой. Пропущенный целиком
день серию обнуляет, рекорд при этом остаётся. Календарь рисуется квадратами
по семь дней с подписью чисел слева (`01–07  🟩⬜🟩…`) и только до сегодняшнего
дня: будущие дни ещё не пропущены. Если сегодня практики не было, раздел прямо
зовёт сказать фразу. Пустая история показывает приглашение, а не нули.
Динамика произношения — средний балл последних попыток против предыдущих,
и она молчит, пока попыток меньше четырёх.

## Отдельная ветка. Админка для владельца

Не видна обычным юзерам, вход по списку id.

```
/admin
  ├─ лимиты          сколько сообщений и разборов в день, длина пробного периода
  ├─ цена подписки
  ├─ статистика      юзеры, платящие, конверсия, расход по сервисам
  └─ рассылка        сообщение всем или сегменту
```

Лимиты в админке это принципиально. Клиент будет крутить их сам, глядя
на конверсию, иначе каждая правка числа превращается в задачу разработчику.

Как сделано (этап 8):

```
/admin
  ├─ 📊 Статистика   юзеры, новые, активные за день и неделю, платящие,
  │                  конверсия, сегодняшние сообщения и разборы, выручка за 30 дней
  ├─ 💸 Расходы      по каждому сервису за сутки / 7 / 30 дней, с итогом
  ├─ 🎚 Лимиты       пять чисел, каждое правится своим экраном  [−5][−1][10][+1][+5]
  ├─ 💎 Цена         цена каждого тарифа тем же рядом кнопок
  ├─ 📣 Рассылка     сегмент → текст → предпросмотр → подтверждение → отчёт
  └─ 🔑 Доступ       кто админ; /admin_add @username, /admin_del @username
```

Чужому `/admin` бот **не отвечает ничего**: любой ответ, даже «нет доступа»,
подтверждает, что админка есть. Попытка пишется в лог и в события.

Правка лимита действует сразу, следующим сообщением юзера: числа лежат в
`settings`, и проверка лимита читает их без кэша. Перезапуск не нужен.

Цена в админке — это **та, которую видит юзер в боте**. Списывает платёжка
свою, заданную в оффере lava.top, поэтому экран цены прямо предупреждает, что
менять надо в двух местах. Расхождение ловится при выставлении счёта и уходит
в лог предупреждением.

Расход считается по журналу `service_calls`: туда ложится каждый вызов
OpenRouter, Whisper, Fish, SpeechSuper и платёжки — длительность, объём и
оценка стоимости по прайсу провайдера. Это оценка, а не счёт, и экран об этом
говорит.

Рассылка уходит в очередь: двадцать сообщений в секунду (телеграм разрешает
тридцать, остаток оставлен живым разговорам), просьбу подождать уважает,
заблокировавших бота считает отдельно от ошибок и в конце присылает отчёт.

Список админов двойной. Прописанные в `ADMIN_IDS` несменяемы; выданные
командой лежат в базе. Отобрать из бота можно только вторых — иначе один
неверный `/admin_del` оставил бы бота без единого админа.

## Поведение в углах (этап 9)

То, что человек находит не по инструкции, а случайно.

| Что сделал юзер | Что видит |
|---|---|
| Фото, стикер, документ, кружок, музыка | «Пока я понимаю только голосовые и текст» |
| Голосовое длиннее двух минут | Просьба сказать короче, с указанием предела |
| Молчание, шум, слишком короткая запись | «Не расслышал» — норма за это не списывается |
| Сказал вторую фразу, не дождавшись ответа | «Секунду, ещё отвечаю на прошлое» |
| Дважды быстро ткнул платную кнопку | Всплывашка «Уже показано выше», второго вызова нет |
| Внешний сервис лёг | Понятное сообщение, списанный слот возвращается |

Замок круга — не придирка к нетерпеливым. Два голосовых подряд запускали два
круга, и оба оплачивались на всех четырёх сервисах, хотя ответ на первое юзер
ещё даже не слышал. Замок ставит бот, принимая реплику, снимает воркер, когда
круг закончился, а срок жизни страхует смерть воркера между этими моментами.

Недоступность сервиса выглядит не аккуратным кодом ответа, а обрывом связи или
таймаутом, поэтому такой сбой заворачивается в общую ошибку провайдера ещё в
слое логирования вызовов. От этого зависят две вещи: запасная озвучка
включается и когда основная не ответила вовсе, а не только когда ответила
пятисоткой; и юзер получает «оценка не работает, разговор идёт как обычно»
вместо общего «что-то пошло не так».

---

## Что юзер НЕ видит

Ни выбора модели, ни токенов, ни названий сервисов, ни настроек качества.
Всё это внутренняя кухня. Наружу торчат только сообщения и понятные счётчики.
